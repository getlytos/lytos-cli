# ISS-0113 — The help must reflect the commands that shipped

## Context

Sprint #04 shipped `lyt next`, `lyt park`/`unpark` and `lyt budget` — but the examples block of
`lyt --help` never mentioned them. An incomplete help is an invisible command.

## The gesture

Add a "Loop primitives (ADR-0004)" group to the `lyt --help` examples, restating that the CLI
exposes the primitives and the wrapper/App orchestrate them.

**The NO_GO is procedurally rejected, and the issue is widened by field feedback.**

that; returning NO_GO on it makes the issue unpassable by construction. That contract is now
fixed: `GO_PENDING_HUMAN` is the correct verdict for this exact shape.

verbs — that block is generated by commander and cannot drift — but the hand-written **Examples**
block was missing seven: `show`, `lint`, `doctor`, `archive`, `claim`/`unclaim`, `update`. `show`
is the one the rules call "the first call of every session". All are now present.

This issue's own Notes said "remember to re-sync the help with every new command". A note is not
a gate. `tests/cli.test.ts` now parses the generated Commands block and fails if any verb lacks an
example — the reminder is now enforced.
